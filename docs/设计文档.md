# 词网探索 — 系统设计文档

## 1. 系统架构

```
┌──────────────────────┐      HTTP/JSON      ┌──────────────────┐
│   React + Vite SPA   │ ◄─────────────────► │   Go HTTP Server  │
│   (frontend)         │    /api/explore      │   (backend)       │
│                      │    /api/generate     │                   │
│                      │    /api/extract      │   :8080           │
│   port: 5173 (dev)   │                      │                   │
│   static (prod)      │                      │   ┌───────────┐  │
└──────────────────────┘                      │   │ LLM Proxy │  │
                                              │   └─────┬─────┘  │
                                              └─────────┼────────┘
                                                        │
                                                        ▼
                                              ┌──────────────────┐
                                              │  OpenRouter API  │
                                              │  or DeepSeek API │
                                              └──────────────────┘
```

### 1.1 部署模式
- **开发模式**: Vite Dev Server + Go Backend（Vite 代理 /api 到 Go）
- **生产模式**: Go 编译单二进制，内嵌静态文件服务，直接运行

## 2. 后端设计

### 2.1 技术栈
- 语言: Go 1.22
- 依赖: 零外部依赖（仅标准库）
- HTTP 框架: `net/http` 标准库

### 2.2 核心模块

```
main.go
├── callLLM()           # 通用 LLM 调用（OpenAI 兼容接口）
├── parseWordsFromLLM() # 解析 LLM 返回为词列表
├── handleExplore()     # POST /api/explore
├── handleGenerate()    # POST /api/generate
├── handleExtract()     # POST /api/extract
├── gzipMiddleware()    # 静态资源 gzip 压缩
└── main()              # 启动入口
```

### 2.3 API 接口

#### POST /api/explore
```
Request:  { "words": ["AI"], "lang": "en" }
Response: { "words": ["machine learning", "deep learning", ...] }
```
- 调用 LLM 生成 20 个语义关联词
- 系统 prompt: "You are a semantic association engine"
- 指令: 根据种子词生成 20 个关联词，使用与输入相同的语言

#### POST /api/generate
```
Request:  { "words": ["AI", "ML"], "lang": "en", "existing": "" }
Response: { "article": "**title**\n\ncontent..." }
```
- 调用 LLM 生成短文（100-150 词）
- 支持 `existing` 字段进行续写
- 使用高维语义引导：LLM 以词为方向但不强制每词出现

#### POST /api/extract
```
Request:  { "text": "...", "lang": "en" }
Response: { "words": ["keyword1", "keyword2", ...] }
```
- 从给定文本中提取所有关键词

### 2.4 LLM 配置
```
环境变量:
  OPENROUTER_API_KEY  // 优先
  DEEPSEEK_API_KEY    // 备选
  LLM_MODEL           // 默认 "openrouter/free"
  LLM_BASE_URL        // 默认 "https://openrouter.ai/api/v1"
```

### 2.5 错误处理
- LLM 调用失败 → 返回 `{"error":"LLM call failed"}`
- JSON 解析失败 → 返回 `{"error":"invalid JSON"}`
- 空参数 → 返回 `{"error":"words required"}`
- HTTP 客户端 45s 超时

### 3.3 状态管理
```
种子词输入:  seedInput
当前词列表:  currentWords[]
选中词:      selectedWords Set<string>
中央区词:    centerWords[]
历史路径:    history[]
集合:        collections[] (localStorage 持久化)
文章:        article
语言:        lang
布局:        layout
自动选中:    autoSelect
加载中:      loading / articleLoading / extracting
错误:        error
```

### 3.4 关键交互

#### 悬停自动选中
- `onMouseEnter` → 设置 500ms 定时器 → 到时间后 `toggleWord`
- `onMouseLeave` → 清除定时器
- 受 `autoSelect` 状态控制，可在设置面板关闭

#### 探索迭代
```
handleContinueExplore():
  selected = selectedWords 或 currentWords
  centerWords += selected (去重)
  push history
  explore(selected)
```

#### 文章续写
```
handleContinueWriting():
  POST /api/generate { words, existing: article }
  article += '\n\n' + response.article
```

### 3.5 数据持久化

## 4. 数据流

### 4.1 探索流程
```
用户 → 输入种子词 → handleInitialExplore()
  → setCenterWords([seed])
  → explore([seed])
    → POST /api/explore { words: [seed] }
    → setCurrentWords(response.words)
    → 展示 20 个词卡

用户 → 选中词（点击/悬停） → toggleWord()
  → selectedWords Set 更新

用户 → 点击"探索选中" → handleContinueExplore()
  → centerWords += selected
  → history.push(snapshot)
  → explore(selected)
    → 新一批 20 个词
```

### 4.2 生成文章流程
```
用户 → 点击"✍ 生成文章" → handleGenerate()
  → seeds = centerWords + activeCollectionWords
  → POST /api/generate { words: seeds }
  → article = response.article
  → Markdown 渲染展示

用户 → 点击"续写" → handleContinueWriting()
  → POST /api/generate { words: seeds, existing: article }
  → article += response.article
```

## 6. 安全

- API Key 仅在后端环境变量中，不向前端暴露
- 前端通过 `/api/*` 路径代理请求，无直接跨域问题
- Markdown 渲染使用 `marked` + `dangerouslySetInnerHTML`，内容来源为 LLM，可控风险
